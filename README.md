# Oh My Bank · Frontend

React 19 · TypeScript · React Router 7 · Vite 8 기반 금융거래 시뮬레이션 고객 화면입니다. 실제 금융상품 판매, 대출 심사, 자금 이동을 제공하지 않습니다.

## 개발 실행

Node.js 24 LTS와 npm을 사용합니다. 백엔드를 `http://127.0.0.1:8080`에서 실행한 다음:

```sh
npm ci
npm run dev
```

`http://127.0.0.1:5173`에서 접속합니다. 해당 포트를 사용 중이라면 `npm run dev -- --port 15173`처럼 다른 포트를 지정합니다. 브라우저 요청은 `/api/v1`을 사용하며 Vite가 백엔드로 프록시합니다. 개발 도중 호스트를 `localhost`와 `127.0.0.1` 사이에서 바꾸면 세션 쿠키가 공유되지 않으므로 한 주소를 일관되게 사용합니다.

## 현재 제공 범위

- 테스트 고객 회원가입, 로그인·로그아웃, 세션 복원
- 비로그인 사용자도 이용할 수 있는 공개 홈과 실제 업무 바로가기
- 상품 목록·상세와 정책 버전·고정금리·한도·기간 조회
- 고객의 대출 신청, 필수 값·원 단위 금액·상품 조건 검증
- 신청 내역과 신청 당시 상품 조건 조회
- 직원 역할 구분과 현재 구현 범위 안내
- 모바일 레이아웃, 처리 중·빈 목록·연결 실패·권한 오류 표시
- 이용 절차와 가상 데이터 사용 범위를 설명하는 공개 이용 안내

심사 승인·거절, 약정, 실행, 상환과 운영 관리 화면은 후속 범위입니다. 화면의 신청 통계는 서버 조회 결과만 표시합니다.

## 인증과 신청 재시도

동일 출처의 HttpOnly 세션 쿠키와 CSRF 토큰을 사용합니다. 변경 요청 전에 `/auth/csrf`를 조회하며 로그인·로그아웃 후 토큰 캐시를 비웁니다. 비밀번호와 인증 토큰을 브라우저 저장소에 저장하지 않습니다.

`AuthProvider`가 세션 복원과 로그인 상태를 공유하며 React Router에서 고객·직원 경로를 구분합니다. 서버는 역할과 고객 소유권을 최종 검증합니다.

공개 홈은 `/`, 고객 신청 조회는 `/my`입니다. 고객 로그인·가입 후 기본 경로는 `/my`, 직원은 `/staff`입니다. 상품 상세에서 로그인하면 검증된 내부 복귀 경로를 사용합니다. `/guide`의 이용 안내는 비로그인 사용자에게도 제공하며, 금융 API의 `/api/v1` 경로는 바뀌지 않습니다.

대출 신청 폼은 동일한 요청 본문을 재시도할 때 같은 `Idempotency-Key`를 유지합니다. 조건을 바꾸거나 접수가 완료되면 새 키를 사용합니다. 화면을 떠나거나 새로고침하면 키가 초기화되므로 결과가 불분명한 경우 먼저 대시보드의 신청 내역을 확인합니다. 백엔드가 요청 키의 재사용과 충돌을 최종 검증합니다.

백엔드 `local` 프로필의 가상 고객은 `customer@omb.local` / `OmbDemo123!`입니다. 직원은 `reviewer@omb.local`, `admin@omb.local`이며 같은 개발용 비밀번호를 사용합니다. 실제 개인정보를 입력하지 마세요. 다른 프로필에서는 개발 계정이 생성되지 않습니다.

## 검증

```sh
npm run format:check
npm run typecheck
npm test
npm run build
```

Vitest는 신청 재시도 키 유지·변경·완료 후 초기화, CSRF 검증 선행, 실패한 CSRF 조회 시 변경 요청 차단, 네트워크 오류 시 자동 재전송 방지와 세션 변경 후 토큰 갱신을 확인합니다. 빌드에 TypeScript 타입 검사(`tsc --noEmit`)가 포함됩니다. 인증·상품 선택·신청·결과 조회·로그아웃은 실제 API와 연결해 데스크톱과 모바일에서 확인합니다.

## 은행형 UI·UX

KB국민은행과 하나은행의 상단 업무 메뉴, 로그인 유틸리티, 빠른 업무 바로가기, 상품 조건 구획을 참고합니다. OMB의 녹색·청록색을 사용하고, 은행 로고·캐릭터·광고 이미지를 복제하지 않습니다. 상품의 금리·한도·기간과 신청 상태를 일정한 순서로 표시하고, 신청은 `상품 선택 → 신청정보 입력 → 접수 완료`의 현재 제공 범위로 안내합니다.

공개 홈·이용 안내·상품 조회와 로그인 후 본인 신청 조회를 구분합니다. 계좌이체, 실제 잔액, 인증서·OTP, 존재하지 않는 공지·상담번호 등은 제공하는 기능처럼 표시하지 않습니다.

반응형 검증에서는 데스크톱·태블릿·모바일의 메뉴, 조건 비교, 신청 폼과 가로 넘침을 확인합니다. 구현·검증 기록을 구분하며 이 안내 자체를 검증 통과 기록으로 사용하지 않습니다.

통합 저장소의 `docs/decisions/0001-react-and-ui.md`에는 React 전환의 범위·비용과 FinMATE 기술 스택을, `docs/decisions/0002-bank-experience.md`에는 현재 은행형 화면과 경로 선택의 근거를 기록합니다.

## 컨테이너

통합 저장소의 `infra/compose.yaml`로 실행합니다. 프런트엔드 이미지는 Node.js 24에서 빌드한 정적 파일을 Nginx로 제공합니다. `/api/`는 `backend:8080`으로 전달하며, `/health`는 컨테이너 상태 확인용입니다.

개발 도구의 기준은 [React 공식 문서](https://react.dev/learn), [React Router 공식 문서](https://reactrouter.com/), [Vite 공식 가이드](https://vite.dev/guide/)입니다. 설치 버전은 `package-lock.json`으로 고정합니다.
