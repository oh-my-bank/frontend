# Oh My Bank · Frontend

React 19 · TypeScript · React Router 7 · Vite 8 기반 은행업 학습·모의 서비스 화면입니다. 은행업 개념을 배우고, 예금·적금·대출을 계산하고, 나의 전략을 세우고, 가상 시간으로 예·적금을 운용하며, 대출 창구 업무를 체험합니다. 실제 금융상품 판매·추천, 대출 심사, 자금 이동을 제공하지 않습니다.

## 개발 실행

Node.js 24 LTS와 npm을 사용합니다. 백엔드를 `http://127.0.0.1:8080`에서 실행한 다음:

```sh
npm ci
npm run dev
```

`http://127.0.0.1:5173`에서 접속합니다. 해당 포트를 사용 중이라면 `npm run dev -- --port 15173`처럼 다른 포트를 지정합니다. 브라우저 요청은 `/api/v1`을 사용하며 Vite가 백엔드로 프록시합니다. 개발 도중 호스트를 `localhost`와 `127.0.0.1` 사이에서 바꾸면 세션 쿠키가 공유되지 않으므로 한 주소를 일관되게 사용합니다.

## 현재 제공 범위

- 은행업 학습(`/learn`, `/learn/:slug`): 분류별 개념 카드, 계산 예시·흔한 오해·체크리스트·공식 출처, 확인 문제 서버 채점. 용어 사전(`/glossary`): 검색·분류를 URL 쿼리와 동기화
- 계산기(`/tools`, `/tools/:kind`): 정기예금·적금·대출 상환 일정·DSR·목표 저축, 규칙·모의 금리표(교육용 가정값)와 제도 수치 출처. 금액은 서버 응답만 표시하고 그래프는 같은 값을 표로도 제공
- 나의 전략(`/strategy`): 4단계 입력 → `BANK_STRATEGY_V1` 실행 항목·월 배분, 결과로 모의 운용 시작(가입 후에도 `/simulation`으로 이어짐)
- 모의 운용(`/simulation`, `/simulation/accounts/:id`, 고객 전용): 가상 자금 샌드박스, 정기예금·적금 가입 확인, 시간 진행(1일~12개월), 만기 예상 vs 오늘 해지 비교, 중도해지, 원장·이벤트. 명령마다 멱등 키(불명확한 실패만 같은 키 재시도)
- 테스트 고객 회원가입, 로그인·로그아웃, 세션 복원
- 비로그인 사용자도 이용할 수 있는 공개 홈과 실제 업무 바로가기
- 상품 목록·상세와 정책 버전·고정금리·한도·기간 조회
- 고객의 대출 신청, 필수 값·원 단위 금액·상품 조건 검증
- 신청 내역과 신청 당시 상품 조건 조회
- 직원 역할 구분과 현재 구현 범위 안내
- 운영 관리자(ADMIN) 상품 관리: 상품 목록(판매 상태·현재 정책 버전), 상품 등록, 정책 버전 이력, 새 정책 발행, 되돌릴 수 없는 판매 중지
- 모바일 레이아웃, 처리 중·빈 목록·연결 실패·권한 오류·세션 만료 표시
- 이용 절차와 가상 데이터 사용 범위를 설명하는 공개 이용 안내

심사 승인·거절, 약정, 실행, 상환과 감사 조회 등 그 밖의 운영 화면은 후속 범위입니다. 상품명·설명 수정과 재활성화는 API가 없으므로 화면에도 없습니다. 화면의 신청 통계는 서버 조회 결과만 표시합니다.

## 인증과 신청 재시도

동일 출처의 HttpOnly 세션 쿠키와 CSRF 토큰을 사용합니다. 변경 요청 전에 `/auth/csrf`를 조회하며 로그인·로그아웃 후 토큰 캐시를 비웁니다. 비밀번호와 인증 토큰을 브라우저 저장소에 저장하지 않습니다.

`AuthProvider`가 세션 복원과 로그인 상태를 공유하며 React Router에서 고객·직원 경로를 구분합니다. 서버는 역할과 고객 소유권을 최종 검증합니다.

공개 홈은 `/`, 고객 신청 조회는 `/my`입니다. 고객 로그인·가입 후 기본 경로는 `/my`, 직원은 `/staff`입니다. 운영 관리자 화면은 `/admin/products`(목록), `/admin/products/new`(등록), `/admin/products/:id`(상세·이력·판매 중지), `/admin/products/:id/policies/new`(정책 발행)입니다. ADMIN이 아닌 계정이 직접 접근하면 관리자 API를 호출하지 않고 권한 안내만 보여 주며, 서버도 403으로 거부합니다. 세션이 만료돼 로그인으로 이동한 ADMIN은 다시 로그인하면 이용하던 `/admin/...` 화면으로 돌아갑니다. 상품 상세에서 로그인하면 검증된 내부 복귀 경로를 사용합니다. `/guide`의 이용 안내는 비로그인 사용자에게도 제공하며, 금융 API의 `/api/v1` 경로는 바뀌지 않습니다.

대출 신청 폼은 동일한 요청 본문을 재시도할 때 같은 `Idempotency-Key`를 유지합니다. 조건을 바꾸거나 접수가 완료되면 새 키를 사용합니다. 화면을 떠나거나 새로고침하면 키가 초기화되므로 결과가 불분명한 경우 먼저 대시보드의 신청 내역을 확인합니다. 백엔드가 요청 키의 재사용과 충돌을 최종 검증합니다.

관리자 변경(등록·정책 발행·판매 중지)은 모두 확인 대화상자를 거치며 `Idempotency-Key`를 요청 내용에 묶어 둡니다. 응답을 받지 못했거나 5xx로 결과가 불명확하면 같은 키로만 다시 보내고, 화면에서 등록·반영 여부를 먼저 조회할 수 있습니다. 정책 발행은 화면에 보여 준 현재 버전을 `expectedCurrentVersion`으로 보내며, 다른 관리자가 먼저 발행해 409 `POLICY_VERSION_CONFLICT`가 오면 최신 정책을 다시 불러와 직접 바꾼 항목만 유지한 채 다시 확인받습니다. 변경 요청이 403이면 `/auth/me`로 세션 만료·권한 변경·CSRF 갱신을 구분합니다.

백엔드 `local` 프로필의 가상 고객은 `customer@omb.local` / `OmbDemo123!`입니다. 직원은 `reviewer@omb.local`, `admin@omb.local`이며 같은 개발용 비밀번호를 사용합니다. 실제 개인정보를 입력하지 마세요. 다른 프로필에서는 개발 계정이 생성되지 않습니다.

## 검증

```sh
npm run format:check
npm run typecheck
npm test
npm run build
```

Vitest는 신청 재시도 키 유지·변경·완료 후 초기화, CSRF 검증 선행, 실패한 CSRF 조회 시 변경 요청 차단, 네트워크 오류 시 자동 재전송 방지와 세션 변경 후 토큰 갱신을 확인합니다. 관리자 화면에 대해서는 서버와 같은 정책 조건 검증(금리 셋째 자리·금액·기간 상한·최소≤최대), 필드 오류 키(`policy.maxAmount` 등) 연결, 불명확한 결과 판정, 충돌 후 재기준, 관리자 로그인 복귀 경로를 확인합니다. 빌드에 TypeScript 타입 검사(`tsc --noEmit`)가 포함됩니다. 인증·상품 선택·신청·결과 조회·로그아웃은 실제 API와 연결해 데스크톱과 모바일에서 확인합니다.

## 은행형 UI·UX

KB국민은행과 하나은행의 상단 업무 메뉴, 로그인 유틸리티, 빠른 업무 바로가기, 상품 조건 구획을 참고합니다. OMB의 녹색·청록색을 사용하고, 은행 로고·캐릭터·광고 이미지를 복제하지 않습니다. 상품의 금리·한도·기간과 신청 상태를 일정한 순서로 표시하고, 신청은 `상품 선택 → 신청정보 입력 → 접수 완료`의 현재 제공 범위로 안내합니다.

공개 홈·이용 안내·상품 조회와 로그인 후 본인 신청 조회를 구분합니다. 계좌이체, 실제 잔액, 인증서·OTP, 존재하지 않는 공지·상담번호 등은 제공하는 기능처럼 표시하지 않습니다.

반응형 검증에서는 데스크톱·태블릿·모바일의 메뉴, 조건 비교, 신청 폼과 가로 넘침을 확인합니다. 구현·검증 기록을 구분하며 이 안내 자체를 검증 통과 기록으로 사용하지 않습니다.

통합 저장소의 `docs/decisions/0001-react-and-ui.md`에는 React 전환의 범위·비용과 FinMATE 기술 스택을, `docs/decisions/0002-bank-experience.md`에는 현재 은행형 화면과 경로 선택의 근거를 기록합니다.

## 컨테이너

통합 저장소의 `infra/compose.yaml`로 실행합니다. 프런트엔드 이미지는 Node.js 24에서 빌드한 정적 파일을 Nginx로 제공합니다. `/api/`는 `backend:8080`으로 전달하며, `/health`는 컨테이너 상태 확인용입니다.

개발 도구의 기준은 [React 공식 문서](https://react.dev/learn), [React Router 공식 문서](https://reactrouter.com/), [Vite 공식 가이드](https://vite.dev/guide/)입니다. 설치 버전은 `package-lock.json`으로 고정합니다.
